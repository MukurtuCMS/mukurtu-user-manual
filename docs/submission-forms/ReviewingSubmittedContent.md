# Reviewing Submitted Content

!!! roles "User roles" 
    Mukurtu manager

Content submitted through a [submission form](UsingSubmissionForms.md) doesn't publish automatically — it waits in a review queue until someone checks it over.

## Find the Pending Submissions queue

From your **Dashboard**, under **Notifications & Review**, select **Pending Submissions**.

The queue lists every submission awaiting review, with its submission title, submitter name, submitter email, submission date, and status.

!!! tip
    Reviewers (and anyone else added to the *Additional reviewers to notify* or *Additional reviewers to email* lists) get an email notification whenever a new submission comes in. See [Configuring notifications](UnderstandingSubmissionForms.md#configuring-notifications).

## Review a submission

Select "Edit" next to a submission to open its content in the normal edit form. From here you can:

- Review and adjust the submitted fields.
- Assign the item to a community and cultural protocol, since submitted content doesn't have these set yet.
- Choose the next step using the site's publishing workflow: select "Publish" to accept the submission and make it visible, or "Save as Draft" to keep working on it before deciding.

!!! requirement
    There's no separate "approve" button. Publishing the item marks the submission as approved; archiving it marks the submission as rejected. Both happen automatically as part of the normal publishing workflow transition.

## Contact the submitter

Select "Contact submitter" next to a submission to send a message straight to the address they provided. This is useful for asking follow-up questions before you decide how to handle the submission, since anonymous submitters don't have a user account you could otherwise message.

1. Enter a *Subject* and *Message*.
2. Select "Send".

Your message is emailed directly to the submitter, with your own email address set as the reply-to.
